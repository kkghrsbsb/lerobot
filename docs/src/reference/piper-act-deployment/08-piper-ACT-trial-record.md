# Piper ACT试验记录

## [Piper ACT](https://zhida.zhihu.com/search?content_id=263308968&content_type=Article&match_order=1&q=Piper+ACT&zhida_source=entity)试验记录（一）

## 一、引言

前面已经对Piper部署ACT（表面上是移植[lerobot](https://zhida.zhihu.com/search?content_id=263308968&content_type=Article&match_order=1&q=lerobot&zhida_source=entity)，本质上移植的是ACT，lerobot实际扮演的是通讯框架的角色）做了很多试验，并认为最后的优化应该集中在数据采集方案上。经过初步的考虑，我尝试了以下几个措施：

1.拉窗帘：考虑到光照对于实验的影响，把窗帘拉起来可以减少日照影响。

2.在原本侧面、顶部两个摄像头的基础上，加入了机械臂末端摄像头。

3.从采集30组数据扩大到采集50组数据。

4.提高示教动作的一致性，并且减慢示教的速度。

## 二、试验结果

首先需要说明的是不能用魔改的ACT进行训练（前面有一篇文章使用了滤波插值的ACT），否则训练会报通道数目异常的错误。

此外，我用的机械臂末端摄像头是[realsense](https://zhida.zhihu.com/search?content_id=263308968&content_type=Article&match_order=1&q=realsense&zhida_source=entity)，realsense的摄像头需要用USB3.0的线，所以我最后购买了一条2m长的USB3.0的线。接口也要USB3.0。

最后的试验效果并不理想。每次夹取的时候都会有一个诡异的右偏，并且训练得到的policy控制下的机械臂抖动也很严重，比较挫败。

## 三、分析与总结

我认为整个试验中最奇怪的点是明明加入了末端摄像头，但是它似乎没有发挥很大的作用，同时我觉得侧面视角的摄像头没有发挥什么作用。所以我考虑接下来的试验要去掉侧面摄像头，然后顶部摄像头要从一个正侧视角进行拍摄，同时保留末端视角。

另一个很奇怪的事情是明明扩大了数据集，泛化性反而变差，我觉得可能和我设置的演示任务过于单一有关。因此考虑下一次试验，随意摆放物块进行示教，采集五十组。

然后我想尝试只通过电脑上可视化的采集到的图像进行抓取，和ACT共享信息。

此外，我打算把垫子撤了，垫子上的字母可能会误导模型训练。

## Piper ACT试验记录（二）

## 一、改进方案

（1）首先需要改进的时摄像头视角。在示范抓取的过程中，我都是站在机械臂的右侧，从右侧上方观察整个抓取过程。所以我的视角和原先输入模型的视角差别很大，原先的视角一个是桌面正上方，一个是桌面侧方，一个在夹爪末端。

我认为夹爪末端的视角一定是有效的。正上方视角理论上也能发挥很大作用，但是在实际抓取时机械臂会遮挡相机对抓取过程的拍摄。侧方视角也理应发挥很大的作用，但是我觉得摆放位置不太合理，所以从侧方视角获取的信息非常有限。

改进的办法就是把正上方的相机移至桌面的右侧上方，近似于我示范动作采集数据时的视角。同时将侧方视角调整至桌面右下角，这样可以更加有效地拍摄抓取物块的关键阶段夹爪上下位置的信息，同时对右上方视角做一个补充。夹爪末端的视角做了保留。

（2）其次，我放弃了“在五个不同位置各采样十组数据”的方案，改为随机挑选位置（由于人的主观选择偏好，没法做到完全随机，但思路是尽量使示范的抓取位置混乱，希望借此模型学习到更加丰富的信息，以此提高模型的泛化性，提升抓取的成功率）。由于第一次试验仓促（偷懒了，暂时还未补实验），仅录制了20组随意摆放并抓取的数据。

（3）最后，我把桌上的垫布换成了没有字母的，原先的垫布是购买lerobot套件厂家送的。以排除字母对模型的可能影响。

## 二、实验结果

虽然只采集了20组数据，但是抓取成功率真的提高了很多，能够在不同位置成功抓取。动作抖动依旧存在，但是总体还是比较平稳。
